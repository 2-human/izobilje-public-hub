# proposal-hub composition — Izobilje Hub

Source of truth: `organization-template/library/features/proposal-hub/` (`chassis_version: 2.0.0`).
Composed as **chassis-config**: the chassis was copied unedited (with one recorded exception)
and everything instance-specific is expressed in `content.js`.

This is the first `proposal-hub` instance in the ecosystem that is **not a pitch**. Izobilje is an
umbrella brand, and the hub's function is to hold the architecture and relationships between every
asset the community develops. That difference is carried entirely in config; no chassis behaviour
was changed for it.

## Chassis divergence (two lines)

`index.html` is `hub.html` with two changes. Reproduce with
`diff library/features/proposal-hub/hub.html public/hub/index.html`.

**1. A noindex meta (added).**

```html
<meta name="robots" content="noindex">
```

The hub carries working material (audiences, decisions, roadmap) and was scoped as unlisted. A
`robots.txt` cannot do this job here: the surface is served from a GitHub Pages **project** path
(`/izobilje-public-hub/`), and crawlers only read `robots.txt` at the domain root, which this repo
does not control. Chassis 2.0.0 exposes no `robots` config key, so a static meta is the only
reliable signal. Credo's hub carries the same edit independently, which is evidence the need is
general rather than local.

**Backport candidate 1:** add an optional `robots` key to the config schema so a surface can
declare `noindex` without touching the chassis.

**2. The static `<title>` (changed from `Proposal hub` to `Izobilje Hub`).**

The chassis assigns `document.title` from `HUB.title` at runtime, so the browser tab was already
correct, but the served HTML kept the chassis default. Link unfurls (Slack, WhatsApp, email) read
static HTML and never run the script, so sharing this hub announced it as "Proposal hub" — the one
word this surface is specifically not. Caught on the live response during post-publish verification.

**Backport candidate 3:** have the chassis ship a neutral static `<title>` (or none), since the
runtime already owns the real one and the shipped default is both pitch-shaped and wrong for any
instance that reads it before JS.

## Config-side workaround (no chassis edit)

Chassis 2.0.0 writes `"Proposal for <b>…</b>"` into `#hubProposal` at load, and that string is not
configurable, although the document title next to it *is* (`HUB.title`). For a hub that is not a
proposal the wording is simply wrong. Rather than take a second divergence, `content.js` corrects
that one node on `DOMContentLoaded`, which fires after the chassis IIFE has run.

The hook is guarded on `typeof document.addEventListener === "function"`, not on `document`,
because `validate-content.mjs` loads the config in a vm sandbox whose document stub is `{title:""}`
and would otherwise throw.

**Backport candidate 2:** promote the lede to config (for example `brand.lede`, defaulting to
`"Proposal for <b>{proposalFor}</b>"`), which would remove the workaround and make the chassis
honestly generic rather than pitch-shaped.

## Project inputs

- **Brand tokens** are the live site's own palette (`--forest`, `--honey`, `--cream`), converted
  from HSL, so the hub and izobilje.com read as one brand. Fonts are the site's Lexend/Inter pair.
- **Website artefact** is embedded **by reference**: `WEB` points at
  `https://2-human.github.io/izobilje-public-main-website/` rather than a copy under
  `public/hub/website/`. The hub therefore cannot drift from the real site, and 20MB of imagery is
  not duplicated into a second repo.
- **Required stubs:** `social: []` and a minimal `PF` are present although no social view ships.
  The chassis runs `renderSocial()` on load and throws without them, and
  `validate-content.mjs` does **not** catch it.
- **`STAGES`** is a forward-looking membership/enquiry pipeline. No CRM view ships in v1.
- **No logo mark.** The chassis renders the sidebar logo through
  `filter: brightness(0) invert(1)`, which assumes a monochrome asset with transparency. The only
  logo Izobilje has is an opaque JPG photograph, which the filter flattens into a solid white
  block, so the sidebar runs as a wordmark instead. Supplying an SVG or an alpha PNG and restoring
  one line in `agency` fixes it.

## Views

Four sections, five views: `intro`, `who`, `audiences`, `website`, `decisions`. All are `static`
editorial except `website`, which is an iframe. Adding the next artefact is a `nav` item plus a
`VIEWS` entry plus an `html` key, with no chassis change.
